pmset disablesleep：它究竟做了什么，还有那个无人提及的电池陷阱

如果你搜索过「如何让 MacBook 合盖时不休眠」，一定见过这条命令。它确实有效，而且是唯一真正有效的方案。但它有个未被明确记录的副作用——我们曾因此损坏了一块电池。

这个标志的作用

sudo pmset -a disablesleep 1   # 永不休眠，即使合上盖子
sudo pmset -a disablesleep 0   # 恢复默认行为

pmset 是 Apple 提供的电源管理工具。disablesleep 是一个隐藏参数，它会指示内核级电源管理器拒绝所有休眠请求——包括空闲超时、苹果菜单中的「睡眠」命令，以及合盖休眠（clamshell sleep）。-a 表示该设置同时对电池供电和接通电源两种状态生效。它还会在重启后持续生效，这正是人们常常忘记关闭它的原因。

为什么其他方法在合盖时统统失效

像 Amphetamine 这样的 App，或 caffeinate 命令，都是通过「电源断言」（IOPMAssertionCreateWithName）来工作的。断言相当于告诉系统：「当前有任务在运行，请勿因空闲而休眠」。但合盖路径（clamshell path）并不会检查这些断言——盖子开关被视为一种用户操作（就像从菜单中选择「睡眠」），因此所有断言都会被忽略，Mac 依然会休眠。disablesleep 则工作在更低层级，直接介入电源管理策略本身，所以它是唯一能真正「扛住」合盖的设置。

陷阱：它同时禁用了低电量强制休眠

macOS 通常会在电池电量极低时强制 Mac 进入休眠，以便安全地执行休眠写盘（hibernate），避免断电导致数据损坏。而这次「紧急休眠」在电源管理器看来，也只是一次普通的休眠请求——disablesleep 1 同样会把它一并拒绝。

我们在 2026-08-17 的日志中确认了这一点：01:32 触发了 10% 电量警告，之后日志中再无「Entering Sleep」事件，下一条记录是 06:39 的冷启动。Mac 一直运行到电池彻底耗尽。此前电池健康度显示为「良好」，第二天早上则变成了「较差」。

因此，如果你在笔记本电脑上启用此标志，你必须亲自盯紧电量——因为 macOS 已经不再替你代劳了。

安全使用建议

如果你自己编写脚本调用它，请务必遵守三条规则：

  1. 始终将 disablesleep 1 与「确保执行」的 disablesleep 0 配对使用——例如在脚本退出、出错或定时器到期时自动关闭。
  2. 定期轮询电池状态（用 pmset -g batt 或 IOPSCopyPowerSourcesInfo），并在电量低于你设定的安全阈值时主动重置该标志。
  3. 切勿以「屏幕是否亮着」作为「有人在使用」的判断依据。录音或转录类 App 可能因断言卡住，导致屏幕整夜不灭。
