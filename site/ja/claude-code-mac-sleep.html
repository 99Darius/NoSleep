Macのスリープ時にClaude Codeが停止するのを防ぐ

20分かかるエージェント処理を開始してからコーヒーを淹れようとノートPCの蓋を閉じ、戻ってきたらセッションが完全に死んでしまった——このような経験はありませんか？Claude Code、Codex CLI、Cursorのエージェント、Ollama、Aiderなど、すべてのAIコーディングツールでこの問題が発生します。でもそれはツールのせいではありません。macOSの仕様によるものです。

なぜエージェントが停止してしまうのか

Macがスリープすると、すべてのプロセスが一時停止（フリーズ）します。ネットワーク接続はタイムアウトし、エージェントのAPIストリームも途切れます。Macをウェイクアップしても、ほとんどのツールは中断したターンを再開できません。蓋を閉じると即座にスリープが開始され、画面を開けたままでも一定時間アイドル状態が続くと設定されたタイムアウト後にスリープに入ります。どちらの場合も、実行中の処理は失われてしまいます。

試す人が多いが、実際には効果のない方法

  • 「ディスプレイがオフのときにスリープしない」というシステム設定は、電源アダプタ接続時のみ有効であり、バッテリー駆動時の「クラムシェルスリープ」（蓋を閉じたときのスリープ）を防げません。
  • caffeinate や Amphetamine は画面を点灯させ続けますが、バッテリー駆動時に蓋を閉じると効果がなくなります。
  • ノートPCを半開きのまま持ち歩く——これは確かに動作しますが、見た目はかなり不審です。実は、NoSleepの開発のきっかけとなったのも、まさにこの方法でした。
  • tmux / nohup はSSH切断後もプロセスを維持できますが、マシン自体がスリープした場合は無力です。

実際に効果がある方法

Macに対して、システムレベルでスリープを禁止する必要があります（pmset disablesleep）。ただし、作業が終わってもスリープを許可しないと、丸一日起動し続け、バッテリーを完全に消耗させてしまいます。 NoSleep はこの両方を自動で処理します：

  1. ⌘⌃S を押すだけ。Smart NoSleepが有効になります。
  2. 蓋を閉じても、Claude Codeはそのまま実行を続けます。
  3. NoSleepはエージェントプロセスを監視し、15分間（設定可能）アイドル状態が続くと、Macを自動でスリープさせ、いつ・何が実行されていたかを通知します。
  4. バッテリー残量が5%に達した場合、モードに関係なく即座にスリープ許可を解除します。

Smartモードで検出されるエージェントは？

実行中のプロセスとして認識されるものならすべて対応： claude、codex、cursor、ollama、aider、gemini などのCLIエージェント。検出はプロセス名に基づいて行われるため、独自のスクリプトでも名前を指定すれば連携可能です。検出機能に頼りたくない場合は、Absolute NoSleepや固定タイマーをご利用ください。

無料・オープンソース・アカウント不要

NoSleepはMITライセンスで、ネイティブSwiftで開発された約1MBの軽量アプリです。テレメトリーやトラッキング機能は一切ありません。署名されていないため、初回インストール時にダウンロードページで説明されている通り、ワンラインの xattr コマンドを実行する必要があります。
