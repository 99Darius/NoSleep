防止 Claude Code 在 Mac 睡眠时中断

你启动一个耗时 20 分钟的 AI 代理任务，合上笔记本去煮杯咖啡，回来却发现会话已死。所有 AI 编程工具都有这个问题：Claude Code、Codex CLI、Cursor 代理、Ollama、Aider……但这并非工具本身的错——根源在于 macOS。

为什么代理会中断

当 Mac 进入睡眠状态时，所有进程都会被冻结：网络连接超时，AI 代理的 API 流中断；唤醒后，工具通常无法恢复到中断前的那一步。合上盖子会立即触发睡眠；保持开盖则会在闲置超时后触发。无论哪种方式，任务都会丢失。

人们常试但无效的方法

  • 系统设置中「显示器关闭时防止睡眠」仅在接通电源时生效，且无法阻止合盖睡眠。
  • caffeinate 或 Amphetamine 可阻止屏幕关闭，但在电池供电且合盖时完全失效。
  • 半开合着笔记本四处走动。确实管用，但看起来很滑稽——NoSleep 最初就是这么诞生的。
  • tmux / nohup 能在 SSH 断连后保持进程运行，却无法抵御整机睡眠。

真正有效的方案

必须在系统层面告诉 Mac 不要睡眠（pmset disablesleep），并在任务完成后主动让它恢复睡眠——否则它会整夜运行，彻底耗尽电量。NoSleep 正是为此而生：

  1. 按下 ⌃⌘S。智能模式（Smart NoSleep）即刻启用。
  2. 合上盖子。Claude Code 继续运行。
  3. NoSleep 持续监控 AI 代理进程：一旦检测到它们连续空闲 15 分钟（可自定义），便自动允许 Mac 睡眠，并推送通知，告知睡眠时间及当时运行的任务。
  4. 若电池电量降至 5%，无论当前处于何种模式，NoSleep 都会立即释放睡眠限制。

智能模式支持检测哪些代理？

任何作为进程运行的工具均可识别：claude、codex、cursor、ollama、aider、gemini 等主流 CLI 代理。检测基于进程名，因此你自己的脚本只要指定名称，同样适用。如不希望依赖进程检测，也可选用 Absolute NoSleep 或固定计时模式。

免费、开源、无需账号

NoSleep 采用 MIT 协议，原生 Swift 编写，体积仅约 1 MB，且不含任何遥测功能。它未签名——首次安装只需一行 xattr 命令（详情见 下载页）。
