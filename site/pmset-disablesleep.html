pmset disablesleep: what it does, and the battery trap nobody mentions

If you've searched for how to keep a MacBook awake with the lid closed, you've seen this command. It works. It's also the only thing that works. But it has a side effect that isn't documented anywhere obvious, and it cost us a battery.

What the flag does

sudo pmset -a disablesleep 1   # never sleep, even with the lid closed
sudo pmset -a disablesleep 0   # back to normal

pmset is Apple's power-management tool. disablesleep is a hidden key that tells the kernel's power manager to reject all sleep requests — idle timeouts, the Apple-menu Sleep command, and clamshell sleep alike. -a applies it on battery and on charger. It survives reboots, which is exactly why forgetting to reset it is so common.

Why nothing else survives a closed lid

Apps like Amphetamine and the caffeinate command work through power assertions (IOPMAssertionCreateWithName). An assertion says "something is happening, don't idle-sleep". The clamshell path doesn't consult assertions — the lid switch is treated as a user action, like choosing Sleep from the menu. So assertions are ignored and the Mac sleeps. disablesleep operates a level below that, in the power-manager policy, which is why it's the only setting that holds.

The trap: it also disables low-battery sleep

macOS normally forces the Mac to sleep when the battery gets critically low, so it can hibernate cleanly instead of losing power mid-write. That emergency sleep is, as far as the power manager is concerned, just another sleep request — and disablesleep 1 rejects it too.

We confirmed this on a 2026-08-17 log: the 10% warning fired at 01:32, there was no "Entering Sleep" event afterwards, and the next entry was a cold boot at 06:39. The Mac had run until the battery hit zero. Battery health, which had read "Good", read "Poor" the next morning.

So if you use this flag on a laptop, you have to watch the battery, because macOS no longer will.

Using it safely

Three rules if you script this yourself:

  1. Always pair disablesleep 1 with a guaranteed disablesleep 0 — on exit, on error, on a timer.
  2. Poll the battery (pmset -g batt or IOPSCopyPowerSourcesInfo) and reset the flag below a threshold you're comfortable with.
  3. Don't rely on "the display is on" as proof someone is there. A stuck assertion from a recording or transcription app can hold the screen on all night.
